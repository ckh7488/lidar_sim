# 환경·생성기 검토실 v24

## 실행과 검토

`python tools/build.py` 다음 `node tools/review-server.cjs`를 실행하고 `http://127.0.0.1:18769/`를 엽니다. `--port 18770`처럼 다른 로컬 포트를 지정할 수 있습니다. Python 정적 서버에는 생성 API가 없으므로 새 검토실은 Node 서버로 열어야 합니다. 기존 상세 화면도 같은 서버의 `index.html`에서 사용할 수 있습니다.

1. **환경 24개**: 실제 시뮬레이터 메시를 미리보기로 그립니다. 8종 필터와 장면별 물체 목록이 있습니다. 실내는 상부를 화면에서만 잘라 봅니다.
2. **생성기 8종**: 거리오차·먼지·비·눈·안개·햇빛·모서리 혼합·약한 신호의 원리, 확인할 부분과 한계를 설명합니다. 미지원 현상은 따로 접어 둡니다.
3. **직접 생성·경로**: 장소, uint32 시드, 연속 랜덤(기본), 자동 또는 1~40 시작점, 한 순간 또는 10초 시퀀스, 노브를 선택합니다. 생성 전에는 형상만 보입니다.

기본 간격은 1초, 0~10초 11프레임입니다. 2/5/10Hz는 각각 21/51/101프레임입니다. 재생은 저장된 순간 스캔 사이를 넘기며 좌표를 보간하지 않습니다. 무거운 비·눈은 먼저 한 프레임으로 확인하세요. 한 서버는 생성 작업 한 개만 실행합니다. 진행 중 다른 탭은 열어볼 수 있지만 설정 변경은 중지 후 가능합니다.

카메라 드래그=회전, 오른쪽 드래그/Shift 드래그=이동, 휠=확대. 장소 전체·경로 확대·먼지 발생원 확대·위에서 보기 버튼이 있습니다. 지형 표준편차는 실제 프레임 설정으로 메시에도 적용합니다. 추가 물체는 파일의 `sceneLayout.instances`와 동일한 모델·변환으로 표시하며 관측 worker의 메시와 같습니다. 조건이 바뀌면 이전 관측·소품·경로는 초기화합니다. 실내 기본 절단은 Z=2.25m 위 형상·관측점을 화면에서만 숨깁니다. 저장 배열과 관측점 수는 그대로입니다. 점 색·크기도 표시만 바꿉니다.

반사도 표시는 기본 켜짐이며 on/off가 있습니다. 검토 라벨 색으로 전환하면 표면은 청회색, 산란·가짜 반환 label 1은 주황색, 불확실한 표면 label 2는 노란색입니다. label 2를 삭제 정답으로 취급하지 마세요. 반사도 색상은 미교정 proxy이며 미지원 채널은 회색입니다. 운동 표본은 별도 표시이며 관측 수에 포함하지 않습니다.

## 실제 출력 연결

`tools/review-server.cjs`가 `tools/runtime.cjs.createSimulator().run()`을 호출합니다. 기존 UI의 설정 함수와 실제 worker 코드를 사용합니다. 이 검토실에 별도의 물리 모델은 없습니다.

생성 결과를 `tools/frame-export.cjs`로 `outputs/review-demo/<고유 작업 ID>/0000.lsf.gz` 등에 저장합니다. 브라우저는 그 파일을 풀어 **원래 Float32 XYZ**를 그대로 Three.js에 연결합니다. XYZ와 라벨의 SHA-256을 다시 계산해 저장된 해시와 다르면 표시하지 않습니다. 거리오차를 다시 뿌리거나 노이즈 수를 보정하지 않습니다.

`routePreview`는 같은 경로 계획을 실제 지형 높이와 함께 0.1초 간격으로 계산한 101개 좌표·yaw·pitch·roll·시각입니다. 별도의 경로 추정이 아닙니다. 현재 화살표는 파일의 `sensorPose.world`와 몸체 회전행렬 `bodyRotation`를 사용합니다. schema 6에 `sceneLayout`과 6DoF 자세를 포함하며 기존 배열 형식은 유지합니다.

`src/review_demo_viewer.js`는 표시와 LSF 읽기, `src/review_demo.js`는 설정/작업/재생, `configs/review_demo_v23.json`은 소개 글과 허용 생성기 목록입니다. `tools/build.py`가 HTML/CSS/JS를 dist로 복사합니다. 갤러리 24개는 하나의 보조 WebGL 컨텍스트를 재사용해 이미지로 만들고 해제합니다. 메인 뷰어는 컨텍스트 한 개, 디코딩한 장면/프레임 캐시는 각각 최대 세 개입니다.

## 로컬 API

- `GET /api/catalog`: 24개 장면·960개 시작점·생성기 소개.
- `POST /api/jobs`: `{scene,generator,seed,pose,mode,time,fps,controls,edgeMixing,randomScene}`. `pose`는 `random`(기본), `auto` 또는 0~39, `mode`는 `frame|sequence`, `fps`는 1/2/5/10입니다. 헤더 `X-Lidar-Review: 1`이 필요합니다.
- `GET /api/jobs/<id>`: 진행률, 완료한 프레임, 적용 경로 미리보기.
- `POST /api/jobs/<id>/cancel`: worker 중단. 이미 저장한 프레임 유지.
- `GET /api/jobs/<id>/frames/<index>`: 원래 LSF.gz 다운로드.
- `GET /api/jobs/<id>/manifest`: 완료 시 프레임 목록과 요청 설정.

서버는 `127.0.0.1`에만 바인딩합니다. Host/Origin, 숫자 범위, 야외 전용 비·눈을 검사하며 임의 파일 경로나 명령을 받지 않습니다. 디스크 결과는 서버 종료 후에도 남지만 작업 API 목록은 해당 서버 실행 중에만 유지됩니다. 저장된 LSF는 `tools/read_lsf.py` 또는 `tools/binary-frame.cjs`로 계속 읽을 수 있습니다. API에 생성물 삭제 기능은 없습니다.

설정 저장 JSON은 재현용입니다. 설정을 불러와도 자동 생성하지 않습니다. 새 시드가 기존 24개 건물 배치를 새로 만드는 것은 아닙니다. 기본 건물은 유지하며 시드별로 실제 메시 소품을 추가합니다. `randomScene:false`로 추가 배치를 끌 수 있습니다. 한 시퀀스 안에서 소품·사람·차량은 정지하고 센서와 날씨가 이동합니다.

## 검증 범위와 한계

`node tests/review-demo.cjs`는 전체 24개 장면에서 실제 131,072빔 관측을 생성하고, 8종 경로·10초 시퀀스·경로 좌표·재현성·LSF/브라우저 디코더 일치·API 입력 검증·취소를 검사합니다. 생성 산출물과 검사 기록은 새로운 outputs 폴더에 남습니다.

실제 현장 교정·학습 성능은 검사하지 않습니다. 이동 스큐는 기본 OFF이며 선택적으로 열별 획득 시각을 적용합니다. 스캔 내부 날씨장 운동, IMU와 외부 모터 36RPM은 미구현입니다. [시간·좌표 계약](motion-skew-v27.md). 같은 24개 장소를 많이 생성해도 독립 장소 수가 늘지 않습니다. `field_calibrated`와 `training_approved`는 계속 false입니다.
