# 이동 스큐 스위치 (v27)

기본은 **꺼짐**입니다. 센서는 10초 경로를 계속 이동하지만 각 프레임은 한 시각의 스캔입니다. 먼저 이 조건으로 개발한 뒤 **이동 스큐 반영**을 켜서 비교합니다. 거리오차·설치 오차·축 흔들림은 기존 설정을 유지합니다.

## 사람이 사용하는 방법

검토실의 **03 직접 생성·경로 → 이동 스큐 반영**을 선택하고 다시 생성합니다. 기존 상세 시뮬레이터에도 이동 시간 옆에 같은 스위치가 있습니다. 실제 저장된 점군을 뷰어에 표시하며, 화면만 휘게 만드는 효과가 아닙니다.

- 꺼짐: 모든 빔을 프레임 기준 시각·자세에서 계산합니다. 실제 이동 스캔을 IMU로 보정한 결과는 아닙니다.
- 켜짐: 회전 중 열마다 센서 위치·yaw·pitch·roll을 다시 평가해 광선을 발사합니다. 측정한 거리는 프레임 기준 자세로 복원하므로 이동 왜곡이 남습니다.
- 10Hz: 한 바퀴 100ms. 20Hz: 한 바퀴 50ms. **프레임 저장 간격과 별개**입니다. 1초마다 저장해도 스캔 자체가 1초짜리는 아닙니다.
- 설정 저장·불러오기, API, CLI에 같은 값이 전달됩니다. 오래된 설정에 이 항목이 없으면 꺼짐입니다. 켜더라도 정지 센서의 점군에는 이동 왜곡이 생기지 않습니다.

## API와 CLI

```js
await sim.run({
  sensor: 'os1-32-u', scene: 'construction_v1', kind: 'range',
  seed: 73017, time: 3, sequence: true,
  motionSkew: { enabled: false, scanHz: 10 }
});
```

검토 API의 `POST /api/jobs`에도 같은 `motionSkew` 객체를 전달합니다. `enabled`는 boolean, `scanHz`는 숫자 10 또는 20입니다. 모르는 키·잘못된 형식은 거절합니다. 1,024열 초과 사용자 센서 프로필은 20Hz를 허용하지 않습니다. `geometry.motionSkew`나 일반 `controls`로 우회하지 말고 최상위 옵션을 사용합니다.

```sh
node tools/simulate.cjs --sensor os1-32-u --kind range --time 3 --motion-skew off --out outputs/no-skew.lsf.gz
node tools/sequence.cjs --sensor os1-32-u --kind range --motion-skew on --scan-hz 10 --fps 1 --out outputs/skew-sequence
```

기존 출력 파일·폴더를 덮어쓰지 않습니다. `--scan-hz`만 지정해도 스큐를 자동으로 켜지 않습니다. `sequence:false`는 센서 이동 자체를 끄는 옵션이고 스큐 스위치와 독립입니다.

## 광선과 시간 계약

[Ouster 공식 데이터 형식](https://docs.ouster.com/sensor-docs/firmware/3.2/lidar-data)의 measurement column과 column timestamp를 기준으로 **열 단위** 획득을 모델링합니다. 열의 실제 교정 방위각은 profile의 기존 값을 사용하며, 디스태거된 영상상의 열 번호로 시간을 계산하지 않습니다. 채널별 하드웨어 내부 발사 시차는 알려진 값으로 보정하지 않았습니다.

폭 W, 프레임 기준 시각 t, 회전수 f에 대해:

```text
column = rayId % W
offset = ((column + 0.5) / W - 0.5) / f
t_acquire = t + offset
pose_acquire = existing_route(clamp(t_acquire, 0, 10))
```

스캔 중앙을 기준 시각으로 택했습니다. 첫 열과 마지막 열은 각 시간 구간의 중앙에 놓입니다. 0초 전·10초 후에는 센서가 끝점 자세에 정지한 것으로 계산합니다. **시각은 자르지 않습니다.** 따라서 끝점 프레임의 실제 획득 시간은 0~10초 밖으로 최대 반 주기만큼 나갑니다. 모든 프레임의 회전 주기는 동일하고 경로를 충돌 미검증 영역으로 외삽하지 않습니다.

실제 광학 원점·방향에는 획득 시각의 몸체 자세, 설치 기울기, 기존 축 흔들림이 적용됩니다. 메시 교차·표면 반응·날씨 교차는 이 광선으로 계산합니다. 햇빛의 가림도 스큐가 켜지면 획득 열의 원점에서 검사합니다. 최종 좌표는 기준 자세의 광학 원점·방향과 측정 거리로 재구성하므로 자동 deskew되지 않습니다. 축 흔들림 보정 옵션은 이동 스큐를 보정하지 않습니다.

## 내보내기

schema 6의 기존 배열에 `timeOffsets: Float64Array`를 추가했습니다. 반환점 수와 길이가 같고, `rayIds`와 같은 순서입니다. **배열 저장 순서는 시간순이 아닙니다.** 시간순 처리가 필요하면 시각으로 정렬해야 합니다.

- `point_time = scanTiming.referenceTimeS + timeOffsets[i]`, 단위 초.
- 스큐가 꺼지면 모든 offset은 0입니다. 이전 파일에는 배열 자체가 없을 수 있습니다.
- 메타데이터와 `config.scanTiming`에 스위치, 회전수, 시각 기준, 열 간격, 끝점 처리, 날씨 근사를 기록합니다.
- 켜진 상태의 `xyz`는 기준 자세로 배치한 왜곡된 관측입니다. 세계 축을 쓰더라도 실제 표면의 참 세계좌표가 아닙니다. `coordinates` 설명도 이를 명시합니다.
- `sensorPose`는 스캔 중앙의 자세입니다. 경로·재질·참 거리·라벨은 기존처럼 숨겨진 참조 또는 정답입니다. 학습 입력으로 사용하지 않습니다. `timeOffsets`는 관측 시간 채널입니다.
- LSF와 JSON 양쪽에 저장하고, 뷰어는 저장한 좌표를 그대로 사용합니다. 필드 추가 때문에 파일 전체 바이트는 이전 버전과 다르지만 스큐 OFF의 좌표·라벨은 기존과 동일해야 합니다.

## 남은 근사

**이번 스위치는 센서 이동 스큐를 분리하는 기능입니다.** 스캔 중 먼지·강수·안개장은 프레임 기준 시각에 고정하고 프레임 사이에서 움직입니다. 빠른 입자 이동의 스캔 내 효과는 포함되지 않습니다. 빛의 비행 시간 중 센서 운동, 채널 내부 발사 시차, 시계 오차·패킷 손실도 재현하지 않습니다.

**IMU, 추정 자세 기반 deskew, 장치 전체의 36RPM 외부 회전은 미구현**입니다. 현재 6DoF 경로로 생기는 스큐만 켭니다. 실제 크레인의 운동을 재현하려면 별도 회전자 축·편심·시간 동기 자료를 연결해야 합니다. 실측 교정·학습 승인은 계속 false입니다.

## 검사

`node tests/motion-skew-v27.cjs`는 독립 벽 교차 수식과 quaternion 계산으로 병진·회전·6DoF 광선 및 복원 좌표를 검증합니다. 같은 센서가 정지한 경우, 축 흔들림 보정 여부, 0·10초 끝점, ON/OFF 재현성도 검사합니다.

기존 v26의 100조건에서 5초 프레임을 OFF로 다시 생성해 저장된 좌표·라벨 해시와 비교하고, 같은 100조건을 ON으로 생성해 24장면·8생성기·3센서와 10/20Hz를 검사합니다. 이 검사는 100개의 전체 10초 시퀀스를 다시 검사했다는 뜻은 아닙니다. v26의 1,100프레임 검사 기록과 원본은 보존합니다. 결과는 실행 후 `docs/validation.md`에 기록합니다.
