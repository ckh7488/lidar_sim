# 100개 실제 생성 검수 v26

**100조건·1,100프레임의 실행/저장 검사와 100조건의 두 시점 3D 검수를 완료했습니다. 검사한 기능에서 오류는 0건이었지만, 먼지 검출 빈도와 강한 안개·강수의 근거리 집중은 실측 승인하지 않았습니다.**

## 실제 결과 (2026-10-09)

- 24개 기본 장면, 8종 생성기, 100개 서로 다른 시작점·6DoF 경로·소품 배치. 소품은 조건당3~13개입니다.
- 10초×100조건, 1초 간격의1,100프레임, 총38,007,721개 반환점. 5초를 다시 계산한100회 좌표/라벨 해시도 일치했습니다.
- 저장 배열1,100개를 다시 읽고 좌표/라벨 해시, 채널 길이·유한값, 거리오차 분해와 가림을 확인했습니다. 최대 거리 분해 오차는3.82µm로 Float32 반올림 범위입니다.
- 독립 BVH로10,100개 자세와 모든 이동 선분의0.3m 몸체 범위를 확인했습니다. 최고 이동속도1.977m/s, yaw84.36°/s, pitch/roll40°/s 이하입니다.
- 시작점/경로/추가 소품 배치는 각각100개 모두 달랐고 먼지 발생원15개도 모두 달랐습니다. 각 시퀀스 안에서는 기기 각도·소품·발생원이 고정됩니다.
- 비·눈의 동일 입자3,542쌍이 세계 좌표 속도대로 이동했습니다. 최대 Float32 위치 차이는14.49µm입니다. 먼지는 동일 입자의 이동180,700쌍과 질량 수지를 확인했습니다.
- 100조건의5초 프레임을 장소 전체와 경로 확대, 총200개 렌더로 직접 확인했습니다. 일부 조건은 발생원 확대,0/5/10초 이동과 반사도 표시도 확인했습니다. 모든1,100프레임을 육안으로 봤다는 뜻은 아닙니다.
- 최종100조건 생성·재현 계산은 약38.7분이 걸렸습니다. 실제 저장 파일과 `manifest.json` 등은 `outputs/audit-100-v26-1791541405067/`에 보존했습니다.

조건 수는 거리오차17, 먼지15, 비6, 눈5, 안개19, 햇빛5, 모서리17, 약신호16입니다. 범위와 개별 해시는 [기계 판독 검사 기록](validation-v26.json)에 있습니다. 프로그램 통과와 실측 충실도 승인을 구분합니다.

## 재현

```sh
python tools/build.py
node --expose-gc tests/audit-100-v26.cjs
node tests/audit-saved-v26.cjs outputs/audit-100-v26-실제폴더이름
node tools/audit-review-server.cjs outputs/audit-100-v26-실제폴더이름
```

마지막 명령은 http://127.0.0.1:18773/ 에서 이미 생성한 파일을 읽는 검수 갤러리를 엽니다. 별도의 물리 모델이 없으며 본 시뮬레이터의 `ReviewDisplay`와 같은 Three.js 뷰어를 사용합니다. 그림을 클릭하면 저장된 0~10초를 직접 확인할 수 있습니다. 현재 프레임을 다시 생성하지 않습니다.

## 검수 도구 변경

100조건 계획의 초기 초안은 야외 생성기 선택식 때문에 종류가 빠지는 문제가 있어 최종 실행 전에 고쳤습니다. 중단한 초안 출력은 보존하되 최종 100조건 집계에서 제외했습니다. 시뮬레이터 물리·검출·경로 코드는 이번 감사에서 변경하지 않았습니다.

검수용 새 갤러리는 빠른 전환 시 공유 렌더러 작업을 직렬화하고 마지막 요청만 표시합니다. 같은 조건의 시간 이동에서는 카메라 확대를 유지하고 로딩 중임을 표시합니다. 생성 도중에는 완료된 시간까지만 선택하게 해 미완료 프레임을 눌러 이전 결과가 남는 혼동도 막습니다. 이는 저장 좌표를 바꾸지 않습니다.

## 검사 설계

24개 기본 장면에서 각각 4개 조건을 뽑고 경계 조건 4개를 추가한 100개입니다. 서로 다른 100개 실측 장소가 아닙니다. 마스터 시드 20261009로 환경/기기 시드, 날씨 강도와 바람을 고정한 재현 가능한 계획입니다. 검수 파일을 다시 읽어 화면을 만들며 원본 좌표에 효과를 덧씌우지 않습니다.

각 조건은 10초 동안 움직이며 **1초 간격으로 0~10초의 11프레임**을 저장합니다. 10Hz 검사가 아닙니다. 5초 프레임은 다시 계산해 비트 단위 해시를 비교합니다. 경로는 별도의 BVH로 0.1초의 101자세와 모든 선분의 몸체 범위를 검사합니다.

OS1-32 U/G와 OS1-128, 추가 각도 변동 켜짐/꺼짐, ±0.005°/±0.01°, 날씨 강도 변동 켜짐/꺼짐, 새 소품·시작점·6DoF 경로를 포함합니다. 마지막 4조건은 시드 0/4294967295, 비 20mm/h, 눈 농도 10, 안개 시정 50m, 기본 거리오차 꺼짐입니다. 강한 날씨는 경계 검사이며 웹 기본값을 바꾸지 않습니다.

좌표/채널 길이·유한값, ray ID 중복, 거리·오차 분해, 표면 뒤 산란 여부, 세계 입자의 이동, 원본 파일 해시, 먼지 질량 수지·입자 이동, 반사도 지원/미지원, 프레임 간 기기 각도·소품·발생원 고정, 재생 재현성을 확인합니다. 신호 및 반사도는 여전히 미교정 proxy입니다.

## 확인한 검토 항목

**먼지 반환 빈도는 최종 실측 승인을 보류합니다.** 15조건·165프레임에서 먼지 반환은 총 29개이며, 12조건은 전 프레임 0개였습니다. 실제 입자가 존재하고 빔과 만나는 경우에도 현재 단일 반환 수신 모델에서 표면 신호가 이기면 먼지 라벨이 없습니다. 063번 5초는 3,209개 빔의 먼지 교차가 있었지만 최종 먼지 반환은 0개입니다. 025번 5초는 센서 가까이에 입자가 있지만 교차 빔이 0개입니다. 030번은 시작점과 발생원 거리가 약 190m여서 100m 센서 범위 밖입니다. 이들을 단순히 생성 실패 또는 모두 가림 때문으로 분류하지 않았습니다. 밀도·라벨을 사후 조작해 양성 예시를 늘리지 않았습니다.

이번 100조건은 모든 센서×생성기×노브의 전조합 검사가 아닙니다. 예를 들어 먼지 15조건은 OS1-32 G이며 비·눈의 강도 jitter는 이 계획에서 꺼져 있습니다. OS1-32 U/G 각각의 생성기 회귀 검사는 v25 기록을 별도로 참조합니다. 24개 장면과 8종 생성기, 3개 센서가 전체 계획에 포함됐다는 뜻을 센서별 전조합 통과로 확대하지 마세요.

## 해석 범위

수치 검사와 시각 검수는 생성기의 안정성을 확인합니다. 날씨의 실측 충실도나 학습 성능은 확인하지 않습니다. `field_calibrated=false`, `training_approved=false`를 유지합니다. 특히 외부 모터 36RPM/스캔 내 운동 왜곡, 동적 차량·사람, 현장별 광학 검출률은 이번 검사로 구현·교정되지 않습니다.

먼지 발생원과 태양 방향을 센서에 억지로 맞추지 않았으므로 멀거나 가려지거나 시야 밖이면 검출 노이즈가 0개일 수 있습니다. 가까운 거리의 날씨 반환이 많은 현상은 현재 수신 가정의 결과이며, 이번 검수로 실제 Ouster 분포임을 보증하지 않습니다. 모서리 라벨 2와 약한 신호의 거리오차는 산란 라벨 1과 별도로 봅니다.

생성 파일은 outputs에 남기고 Git에는 넣지 않습니다. `plan.json`, `manifest.json`, `saved-data-check.json`, `visual-review.json`을 결과 폴더에 보관합니다. 생성 스크립트는 새 폴더만 만들고 이전 출력에 덮어쓰지 않습니다.
